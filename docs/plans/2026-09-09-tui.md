# rudy TUI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `rudy` with no arguments opens the Bubble Tea v2 client on the embedded server: the design's default screen, vim editing through vimbubble v2, pi's key ids, the Esc semantics, permission prompts inline, status items and widgets from plugins, model and session pickers, slash commands, and teatest goldens for every config permutation the design names.

**Architecture:** The client is a Bubble Tea v2 program in `internal/tui` that speaks only the protocol through `protocol.Client` (a goroutine turns notifications into `tea.Msg`s). Entries become rows (`internal/tui/transcript`), rendered through a theme (`internal/tui/theme`) with glamour for markdown and udiff for edits. Keys resolve through a table of pi action ids (`internal/tui/keys`). The editor is bubbles v2's textarea wrapped by vimbubble v2 (`internal/tui/input`). Layout is ordered slots (`internal/tui/app`). Inline mode commits a turn's rows to scrollback when the turn rests; altscreen keeps a viewport. Nothing in the client imports `internal/server`.

**Tech Stack:** Go 1.26; `charm.land/bubbletea/v2` 2.0.9, `charm.land/bubbles/v2` 2.2.1, `charm.land/lipgloss/v2` 2.0.6, `charm.land/glamour/v2` 2.0.1, `github.com/alecthomas/chroma/v2` 2.27.0, `github.com/aymanbagabas/go-udiff` 0.4.1, `github.com/charmbracelet/x/ansi` 0.11.8, `github.com/charmbracelet/x/exp/teatest/v2` at the commit `go get` resolves today (2.0.0-20260906004030-3986e9119cf9), `github.com/charmbracelet/x/xpty` 0.1.4 for the real path, `github.com/guygrigsby/vimbubble/v2` through a `replace` to `../vimbubble/v2`. All pinned exactly.

**Spec:** `docs/specs/2026-09-07-rudy-design.md` (Client and CLI sections), `docs/adr/0006-bubbletea-v2-and-ui-as-config.md`, `docs/adr/0013-the-tui-wave.md` (the eight decisions this plan implements), `docs/specs/rudy-contracts.md` (`config.toml` `ui.*` and `keys.*` rows, `themes/<name>.toml`, the notification table) and `docs/specs/rudy-domain-model.md` (TranscriptRow, RowKind, Slot, Theme, KeyBinding, Editor, TurnControl). The default screen in the design is the golden for Task 8.

## Global Constraints

- Module `github.com/guygrigsby/rudy`, `go 1.26`, `CGO_ENABLED=0` builds. New dependencies pinned exactly at the versions above; `go.mod` gains `replace github.com/guygrigsby/vimbubble/v2 => ../vimbubble/v2`; CI checks vimbubble out beside rudy the way it does memory.
- `for range n`, never a three-clause count loop.
- The client speaks the protocol only: `grep -rl 'internal/server' internal/tui` is empty. The client never appends entries, never touches the session store, never reads the registry except through `registry.list`. The one exception is `internal/cli`, which builds the server and dials it in memory, as `rudy -p` does.
- Every render choice is a config field with a default, read once at start; a plugin cannot clear another plugin's status item or widget; nothing renders that config did not place. No painted backgrounds: no lipgloss `Background` anywhere under `internal/tui` except the `ui.diff.style = "background"` path.
- Keys: pi's action ids, pi's defaults, pi's `modifier+key` grammar; an unknown action id or an unparseable key in `[keys]` is a config error naming it.
- Esc semantics exactly as ADR 0006 and the domain model's TurnControl table: insert to normal consumed; visual to normal; normal with a turn running once steers, twice within `permissions.double_press_ms` cancels; steering with an empty editor once cancels; idle closes a picker or a selection.
- An unsafe tool's permission question renders inline where its row will be; `y` allows once, `a` allows for the session, `n` denies, Esc denies; the answer goes through `session.answer` with the reason `asker`.
- Tests: `go test -race ./...` green at every commit. teatest v2 goldens under `internal/tui/testdata/`, regenerated only with `-update`, each named for the config permutation it proves. No network in tests; the fake server is `server.New` over `protocol.Pipe` with a scripted provider, as the cli tests do, or a scripted `protocol.Conn` for pure-client tests.
- Commits: terse, verb-first, area prefix (`tui:`, `cli:`, `config:`, `docs:`, `repo:`; in the vimbubble repository `v2:`), no em or en dashes, no Oxford commas, no attribution trailers, one `git commit -m` line.
- Work is tracked in beads under the epic Task 0 creates. Claim the task's issue before starting, close it in the task's final commit step.
